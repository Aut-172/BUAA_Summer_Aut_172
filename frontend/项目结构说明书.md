# 项目结构说明书

## 1. 项目定位

本项目是一个生活服务平台前端原型，围绕四类角色构建：

- 游客：可浏览商家与商品，不可购买
- 普通用户：可购物、下单、评价、管理个人资料
- 商家：可管理店铺资料、商品、规格、订单
- 骑手：可查看任务、接单、配送、完成履约

当前项目以 **Vite + 原生 JavaScript + 本地 mock API** 的形式实现，目标是先把前端交互、页面流程、接口契约跑通，后续便于 Spring Boot / MySQL / Redis 后端接入。

## 3. 核心文件职责

### 3.1 `src/main.js`

前端入口文件。

作用：
- 引入 `app.js`
- 触发整个前端应用初始化

### 3.2 `src/app.js`

项目的核心文件，承担了当前绝大多数前端职责：

- 全局状态定义
- 本地持久化（localStorage）
- 角色权限判断
- hash 路由分发
- 页面 HTML 渲染
- 事件绑定
- 商品、购物车、订单、评价、聊天、商家后台、骑手工作台逻辑

这是目前最重要的业务文件。

### 3.3 `src/api.js`

统一的接口调用入口。

作用：
- 封装 `fetch`
- 统一处理 `/api/...` 请求
- 向页面逻辑暴露接口方法

后端接入时，优先保证这里的方法和接口说明文档一致。

### 3.4 `src/style.css`

项目所有样式定义。

包含：
- 首页样式
- 商品详情样式
- 搜索页样式
- 商家后台样式
- 骑手工作台样式
- 规格选择与评价样式

### 3.5 `vite.config.js`

除了 Vite 配置外，这里还承担了本地 mock 服务的职责。

作用：
- 配置开发端口 `5173`
- 启动本地 mock API 服务 `3001`
- 提供商家、订单、用户、骑手、商家商品等模拟数据
- 模拟真实后端接口行为

后端接入前，这个文件是前端联调的核心支撑。

项目使用 hash 路由，主要页面包括：

- `#/home` 首页
- `#/search` 搜索页
- `#/merchant` 商家详情页
- `#/product/:id` 商品详情页
- `#/product-reviews/:id` 商品评价页
- `#/cart` 购物车
- `#/orders` 订单页
- `#/profile` 角色资料页
- `#/login` 登录注册页
- `#/merchant-dashboard` 商家后台
- `#/merchant-product-editor/:id` 商家商品编辑页
- `#/rider-dashboard` 骑手工作台
- `#/chat` 客服聊天页

## 6. 状态管理方式

当前没有使用 Vue / React / Pinia，而是使用原生对象维护状态：

- 全局状态对象：`state`
- 初始化：`defaultState`
- 持久化：`localStorage`
- 页面刷新后恢复：`loadState()`

优点：
- 快速原型开发
- 易于统一收口逻辑

缺点：
- `app.js` 文件职责较重
- 后续复杂度继续提高时建议拆模块

## 7. 角色体系说明

### 游客
- 默认未登录状态
- 可浏览商家、商品、搜索
- 不可购买、不可评价、不可结算

### 普通用户
- 登录账号：`demo / 123456`
- 可购物、下单、支付、取消、确认收货、评价

### 商家
- 登录账号：`merchant01 / 123456`
- 只进入商家资料与商家后台
- 不参与普通用户购物流程

### 骑手
- 登录账号：`rider01 / 123456`
- 只进入骑手资料与骑手工作台
- 不参与购物与商家管理

---

## 8. 接口接入建议

如果后端同学开始接入：

1. 先阅读 `接口说明文档.md`
2. 对照 `src/api.js` 方法清单实现真实接口
3. 用 Spring Boot Controller 保持路径与字段一致
4. 逐步替换 `vite.config.js` 中 mock 实现
5. 保证订单、用户、商家、骑手四类核心实体一致

---

## 9. 后续建议

如果后续继续演进，推荐逐步拆分：

- `src/modules/consumer/*`
- `src/modules/merchant/*`
- `src/modules/rider/*`
- `src/modules/auth/*`
- `src/modules/order/*`

并最终升级为：
- Vue 3
- Vue Router
- Pinia
- Axios

这样更适合多人协作与长期维护。
