# 项目结构说明书

## 1. 项目定位

本项目当前不是单纯前端原型，而是一套生活服务平台阶段性交付系统：前端使用 React + Vite，后端使用 Spring Cloud 微服务，统一通过 API Gateway 暴露 `/api/...` 接口。

系统围绕五类使用身份组织：

- 游客：浏览商家、商品、搜索和公开评价。
- 普通用户：注册登录、维护资料和地址、加购、下单、支付、确认收货、评价和消息沟通。
- 商家：维护店铺资料、商品、规格、库存、查看经营看板和处理本店订单。
- 骑手：维护资料、查看任务、接单、取餐、送达和查看配送统计。
- 管理员：管理用户、商家、骑手和订单。

## 2. 仓库目录结构

```text
life-service/
├─ frontend/                # React + Vite 前端
├─ services/                # Spring Boot 微服务
│  ├─ api-gateway/          # API Gateway
│  ├─ common-lib/           # JWT、Result、Feign 等公共能力
│  ├─ merchant-service/     # 商家、商品、分类、搜索、推荐、商家后台
│  ├─ user-service/         # 用户、地址、购物车、收藏、管理员用户管理
│  ├─ order-service/        # 下单、订单状态、商家订单、管理员订单、内部订单接口
│  ├─ settlement-service/   # 优惠券、锁券、模拟支付、支付查询
│  ├─ fulfillment-service/  # 骑手、配送任务、管理员骑手管理
│  └─ engagement-service/   # 评价、图片上传、消息会话
├─ db/microservices/        # 多 schema 初始化 SQL
├─ configs/                 # Nacos Config、Sentinel 规则等配置材料
├─ k8s/                     # Kubernetes 示例部署清单
├─ load-tests/              # HPA、Sentinel、故障容错探测脚本
├─ scripts/                 # 本地初始化、测试、部署和数据脚本
├─ docs/                    # 微服务边界、治理、实验和运维文档
└─ reports/                 # 测试报告、性能报告和治理实验报告
```

## 4. 关键文件职责

### 4.1 `frontend/src/main.jsx`

负责 React 应用装配、浏览器路由、顶部导航、登录态保护和角色默认跳转。当前主要页面路由包括：

- `/` 首页
- `/search` 搜索页
- `/login` 登录注册页
- `/merchants/:merchantId` 商家详情页
- `/cart` 购物车
- `/checkout` 结算页
- `/orders` 订单页
- `/coupons` 优惠券页
- `/profile` 个人资料页
- `/messages` 消息线程
- `/messages/orders/:orderId` 订单会话详情
- `/reviews/:orderId` 评价页
- `/merchant-center` 商家中心
- `/rider-center` 骑手中心
- `/admin-center` 管理中心

### 4.2 `frontend/src/utils/api.js`

前端统一 API 客户端，基于 Axios 封装：

- 默认 API 基址为 `/api`。
- 运行在 K8s 前端 NodePort `30080` 时，会自动使用同主机 `30081/api`。
- 若配置 `VITE_API_BASE_URL`，优先使用该显式地址。
- 自动追加 `Authorization: Bearer <token>`。
- 统一展开后端 `Result<T>` 和 `PageResult<T>` 响应。

接口清单以 [接口说明文档.md](接口说明文档.md) 为准。

### 4.3 `frontend/src/utils/ApiProvider.jsx`

维护前端登录态、角色身份、token 持久化、登出和全局提示，页面通过 `useSession()` 读取当前用户和 API 实例。

### 4.4 `frontend/src/pages/`

页面组件按业务视图拆分，每个核心页面配有相邻单测，例如 `Cart.jsx` 与 `Cart.test.jsx`。这也是后续定位页面逻辑和补测试的主要入口。

### 4.5 `frontend/e2e/`

Playwright 覆盖 UC01-UC21 场景。E2E 默认通过 `e2e/support/mockApi.js` 模拟后端返回，用于稳定验证前端交互；真实 Gateway 冒烟需使用独立脚本或启动完整后端后运行。

## 5. 后端服务结构

每个业务服务基本遵循以下结构：

```text
services/<service-name>/
├─ src/main/java/.../controller/   # 对外 API 与内部接口
├─ src/main/java/.../service/      # 业务逻辑
├─ src/main/java/.../mapper/       # MyBatis-Plus Mapper
├─ src/main/java/.../client/       # Feign 客户端
├─ src/main/java/.../dto/          # 请求和响应 DTO
├─ src/main/resources/             # application.yml、mapper XML 等
└─ src/test/                       # 单元测试和接口层测试
```

服务边界和数据库归属详见 [../docs/microservices/owner-a-boundary-plan.md](../docs/microservices/owner-a-boundary-plan.md)。

## 6. 数据与调用边界

- 所有前端请求进入 `api-gateway`。
- JWT 鉴权在业务服务侧通过 `common-lib` 完成。
- 服务间访问通过 OpenFeign + Nacos 服务名完成。
- 业务服务不得直接读取其他服务数据库表。
- 跨服务读取或状态推进使用 `/internal/**` 内部接口。
- 多 schema 初始化脚本位于 `db/microservices/init-microservice-schemas.sql`。

## 7. 测试与报告位置

- 后端全量测试：`scripts/test-microservices.ps1`，报告为 `reports/testing/microservice-test-report.md`。
- B 侧专项测试：`scripts/test-b-side-services.ps1`，报告为 `reports/testing/b-side-test-report.md`。
- 前端单测：`cd frontend && npm.cmd run test:ci`。
- 前端 E2E：`cd frontend && npm.cmd run e2e`，默认走 Playwright mock API。
- 性能对比：`reports/performance/performance-comparison-summary.md`。
- Sentinel 治理实验：`reports/sentinel/sentinel-governance-experiment-report-20260903.md`。
- 故障容错实验：`reports/fault/fault-tolerance-experiment-report-20260903.md`。

## 8. 继续演进建议

后续增强优先级建议：

1. 以真实 Gateway 环境补齐消费者、商家、骑手、管理员端到端冒烟脚本。
2. 将支付从模拟成功升级为真实支付网关或回调验签模型。
3. 为骑手分配增加更真实的调度策略和地理位置能力。
4. 将消息从订单会话持久化升级为实时推送或 WebSocket。
5. 持续扩展跨服务故障实验，覆盖下单、支付、骑手接单和评价写入链路。
