# 2 系统需求概述

## 2.1 需求规定

本系统为面向城市居民的综合生活服务平台，支持用户浏览商家、外卖点餐、团购购买、订单管理、评价管理等功能。

### 主要输入

- 用户注册信息
- 登录认证信息
- 商品搜索关键词
- 订单数据
- 支付数据
- 商家商品信息
- 用户评价信息

### 主要输出

- 商家列表
- 商品详情
- 订单状态
- 支付结果
- 配送状态
- 用户评价结果

### 功能性能要求

| 指标         | 要求                 |
| ------------ | -------------------- |
| 登录响应时间 | ≤500ms               |
| 搜索响应时间 | ≤500ms               |
| 系统并发     | ≤10用户              |
| 系统可用性   | 课程演示期间稳定运行 |
| 数据安全     | 密码加密存储         |

------

## 2.2 业务目标

系统建设目标如下：

1. 为用户提供一站式本地生活服务平台；
2. 为商家提供线上经营与订单管理能力；
3. 为骑手提供配送接单能力；
4. 为管理员提供平台运营管理能力；
5. 实现用户、商家、骑手三方业务协同。

------

## 2.4 设计约束

- 后端必须采用 Spring Boot + Spring Cloud
- 前端采用 Vue.js 3
- 数据库采用 MySQL
- 缓存采用 Redis
- 使用 RESTful API
- 支付采用模拟支付
- 不使用 Elasticsearch
- 使用 HTTP 通信方式

------

## 2.7 系统总体架构

系统采用前后端分离 + 微服务架构设计。

### 系统架构图

```text
┌─────────────────────────────┐
│          浏览器客户端         │
└────────────┬────────────────┘
             │ HTTP
┌────────────▼────────────────┐
│        Vue.js 前端系统        │
└────────────┬────────────────┘
             │
┌────────────▼────────────────┐
│     Spring Cloud Gateway    │
└─────┬───────────┬───────────┘
      │           │
 ┌────▼───┐ ┌────▼────┐
 │用户服务│ │订单服务 │
 └────┬───┘ └────┬────┘
      │           │
 ┌────▼───┐ ┌────▼────┐
 │商家服务│ │支付服务 │
 └────┬───┘ └────┬────┘
      │           │
 ┌────▼──────────▼────┐
 │ MySQL / Redis / Nacos │
 └─────────────────────┘
```

### 架构特点

- 前后端分离
- 微服务拆分
- 服务注册与发现
- 统一网关认证
- Redis缓存加速
- RESTful接口通信

## 3.3 系统数据结构设计

### 3.3.1 逻辑结构设计要点

系统核心数据结构如下：

| 数据结构       | 主要字段               |
| -------------- | ---------------------- |
| 用户(User)     | id、username、password |
| 商家(Merchant) | id、name、address      |
| 商品(Product)  | id、name、price        |
| 订单(Order)    | id、status、amount     |
| 评价(Review)   | id、score、content     |
| 优惠券(Coupon) | id、amount、expireTime |

### 数据关系图

```text
用户
 │
 ├──订单
 │    └──订单明细
 │          └──商品
 │
 ├──评价
 │
 └──优惠券

商家
 ├──商品
 ├──订单
 └──评价
```

------

### 3.3.2 物理结构设计要点

| 数据项       | 存储方式 |
| ------------ | -------- |
| 用户信息     | MySQL    |
| 订单信息     | MySQL    |
| Token缓存    | Redis    |
| 热门商家缓存 | Redis    |

### 存储设计原则

- 高频数据使用Redis缓存
- 核心业务数据持久化到MySQL
- 使用主键索引提升查询效率
- 订单表采用状态字段优化查询

------

### 3.3.3 数据结构与程序关系

| 模块     | 涉及数据结构     |
| -------- | ---------------- |
| 用户模块 | User             |
| 商品模块 | Product          |
| 订单模块 | Order、OrderItem |
| 支付模块 | Payment          |
| 评价模块 | Review           |

# 4 系统数据库设计

系统数据库采用 MySQL 8.0。

### 核心表设计

| 表名       | 说明       |
| ---------- | ---------- |
| user       | 用户表     |
| merchant   | 商家表     |
| rider      | 骑手表     |
| product    | 商品表     |
| orders     | 订单表     |
| order_item | 订单明细表 |
| review     | 评价表     |
| coupon     | 优惠券表   |
| payment    | 支付记录表 |
| cart       | 购物车表   |

### 数据库E-R关系

```text
User 1 --- n Orders
Orders 1 --- n OrderItem
Merchant 1 --- n Product
Merchant 1 --- n Orders
User 1 --- n Review
```

### 数据库设计原则

- 遵循第三范式
- 主键统一使用 bigint
- 金额统一使用 decimal(10,2)
- 时间统一使用 datetime
- 使用逻辑删除字段

# 5 运行设计

## 5.1 运行模块组合

系统运行时由以下模块协同完成：

```text
前端模块
   ↓
网关模块
   ↓
业务服务模块
   ↓
数据库模块
```

业务服务模块包括：

- 用户服务
- 商家服务
- 订单服务
- 支付服务
- 搜索服务
- 评价服务

------

## 5.2 运行控制

### 系统启动流程

```text
启动MySQL
    ↓
启动Redis
    ↓
启动Nacos
    ↓
启动各微服务
    ↓
启动Gateway
    ↓
启动Vue前端
```

### 请求处理流程

```text
用户请求
    ↓
Gateway鉴权
    ↓
服务路由
    ↓
业务处理
    ↓
数据库访问
    ↓
返回结果
```

------

## 5.3 运行时间

| 操作     | 响应时间 |
| -------- | -------- |
| 登录     | ≤500ms   |
| 搜索     | ≤500ms   |
| 下单     | ≤1s      |
| 支付     | ≤2s      |
| 页面加载 | ≤2s      |

### 定时任务

| 任务           | 周期    |
| -------------- | ------- |
| 超时订单取消   | 每1分钟 |
| 默认评价生成   | 每天    |
| 优惠券过期检查 | 每小时  |

### 并发设计

- Redis缓存热点数据
- 使用数据库事务保证订单一致性
- 使用乐观锁控制库存
- 网关统一限流
