# VSCode 配置环境指南

## 1. 适用对象

本指南面向第一次接手本项目的同学，目标是：

- 能在 VSCode 中快速打开项目
- 能正确安装运行环境
- 能启动前端开发服务
- 能看到当前完整的角色系统效果

---

## 2. 基础环境要求

请先确保本机已安装：

### 2.1 Node.js

推荐版本：
- Node.js 18 及以上

检查命令：

```bash
node -v
npm -v
```

如果能输出版本号，说明安装成功。

### 2.2 VSCode

推荐使用最新版 VSCode。

建议安装扩展：
- ESLint
- Prettier - Code formatter
- EditorConfig（可选）
- Chinese (Simplified) Language Pack（可选）

---

## 3. 获取项目

将项目代码拉到本地后，在 VSCode 中打开项目根目录：

```text
bighomework/
```

不要只打开 `src/`，否则运行脚本和配置文件不会完整生效。

---

## 4. 安装依赖

在 VSCode 终端中执行：

```bash
npm install
```

安装成功后，会生成 / 更新：
- `node_modules/`

---

## 5. 启动项目

### 5.1 开发模式启动

执行：

```bash
npm run dev
```

默认会启动：
- 前端页面：`http://127.0.0.1:5173/`
- 本地 mock API：由 `vite.config.js` 自动启动

如果浏览器没自动打开，请手动访问：

```text
http://127.0.0.1:5173/
```

### 5.2 生产构建检查

执行：

```bash
npm run build
```

这会验证：
- 代码是否存在语法问题
- 构建是否能成功完成

---

## 6. 常见运行问题

### 6.1 端口占用

如果启动时报错类似：

```text
EADDRINUSE: address already in use :::3001
```

说明本地已有旧的 mock 服务仍在运行。

解决方法：
- 关闭旧终端
- 或结束占用端口的 Node 进程
- 然后重新执行：

```bash
npm run dev
```

### 6.2 页面不是最新代码

如果你已经改了代码，但浏览器效果不更新：

1. 先确认 `npm run dev` 是否仍在运行
2. 刷新浏览器页面
3. 如果仍然不对，重启 dev 服务

### 6.3 账号登录失败

如果商家或骑手账号登录失败，很可能是旧服务未重启。

请确认当前是最新服务，然后使用以下测试账号：

- 普通用户：`demo / 123456`
- 商家：`merchant01 / 123456`
- 骑手：`rider01 / 123456`

## 8. 关键文件说明

你需要重点关注这些文件：

- `src/app.js`
  - 页面逻辑、路由、状态、事件、角色权限
- `src/api.js`
  - 前端统一接口层
- `src/style.css`
  - 样式文件
- `vite.config.js`
  - Vite 配置与 mock 接口实现
- `接口说明文档.md`
  - 前后端接口契约
- `项目结构说明书.md`
  - 项目整体结构说明

---

## 9. VSCode 推荐工作方式

建议：

1. 左侧打开 `src/app.js`
2. 下方开终端运行 `npm run dev`
3. 浏览器打开 `http://127.0.0.1:5173/`
4. 修改代码后直接刷新或等待热更新
5. 提交前执行：

```bash
npm run build
```

---

## 10. 团队协作建议

多人开发时建议遵守：

- 改动前先看 `接口说明文档.md`
- 涉及角色逻辑优先确认是否影响：游客 / 普通用户 / 商家 / 骑手
- 改完必须跑一次：

```bash
npm run build
```

- 如果新增接口，同时更新：
  - `src/api.js`
  - `接口说明文档.md`

---

## 11. 后续后端接入说明

当前项目使用 mock API 驱动。

后端接入时：
- 保持 `/api/...` 路径不变
- 保持 JSON 字段结构不变
- 逐步把 `vite.config.js` 中的 mock 接口替换为真实 Spring Boot 接口即可

前端页面不需要大规模重写。
