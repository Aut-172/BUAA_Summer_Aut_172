# 角色体系与业务流程说明

## 1. 角色划分

当前系统包含五类身份：

- 游客（guest）
- 普通用户（consumer）
- 商家（merchant）
- 骑手（rider）
- 管理员（admin）

前端通过 `frontend/src/main.jsx` 中的受保护路由限制角色访问；后端通过 `services/common-lib` 的 JWT 身份解析和各服务业务校验共同保证权限边界。

## 2. 游客能力

游客无需登录即可：

- 浏览首页。
- 搜索商家和商品。
- 查看商家详情、商品信息、公开评价和评分。
- 进入登录/注册页。

游客不可：

- 加入购物车。
- 结算下单。
- 领取优惠券。
- 查看订单和消息。
- 提交评价。
- 进入商家、骑手或管理中心。

## 3. 普通用户能力

普通用户登录后可执行完整消费链路：

1. 浏览商家和商品。
2. 加入购物车。
3. 维护收货地址和个人资料。
4. 领取和查看优惠券。
5. 提交订单。
6. 模拟支付订单。
7. 查看订单状态和支付记录。
8. 查看配送信息。
9. 与订单参与方发送消息。
10. 确认收货。
11. 提交图文评价。

测试账号：

```text
demo / 123456
```

主要后端服务：`user-service`、`order-service`、`settlement-service`、`fulfillment-service`、`engagement-service`。

## 4. 商家能力

商家登录后可进入 `/merchant-center`：

1. 查看经营看板。
2. 修改店铺资料。
3. 管理商品。
4. 编辑商品规格和库存。
5. 删除商品。
6. 查看本店订单。
7. 推进本店订单状态。
8. 与订单相关用户或骑手沟通。

测试账号：

```text
merchant01 / 123456
```

主要后端服务：`merchant-service`、`order-service`、`engagement-service`。商家看板会通过 `merchant-service -> order-service` 汇总订单数据，依赖故障时具备降级返回能力。

## 5. 骑手能力

骑手登录后可进入 `/rider-center`：

1. 查看骑手资料和配送统计。
2. 查看待接任务、我的任务和已完成任务。
3. 接单。
4. 标记已取餐。
5. 标记送达完成。
6. 修改骑手资料。
7. 与订单相关用户或商家沟通。

测试账号：

```text
rider01 / 123456
```

主要后端服务：`fulfillment-service`、`order-service`、`merchant-service`、`engagement-service`。

## 6. 管理员能力

管理员登录后可进入 `/admin-center`：

1. 查看用户列表并冻结/解冻用户。
2. 查看商家列表并审核、冻结、解冻商家。
3. 查看骑手列表并审核、冻结、解冻骑手。
4. 查看订单列表和订单详情。

测试账号：

```text
admin / admin123
```

主要后端服务：`user-service`、`merchant-service`、`fulfillment-service`、`order-service`。

## 7. 核心业务流转

### 7.1 消费者下单流程

```text
浏览商品 -> 加入购物车 -> 选择地址/优惠券 -> 提交订单 -> 支付 -> 等待接单/配送 -> 确认收货 -> 评价
```

关键接口：

- `POST /api/user/cart`
- `POST /api/checkout`
- `POST /api/orders/{id}/pay`
- `GET /api/orders/{id}`
- `POST /api/orders/{id}/complete`
- `POST /api/reviews`

### 7.2 商家处理流程

```text
商家登录 -> 查看经营看板 -> 查看本店订单 -> 更新订单状态 -> 必要时发送消息
```

关键接口：

- `GET /api/merchant/dashboard`
- `GET /api/merchant/orders`
- `PUT /api/merchant/orders/{id}`
- `GET /api/messages/threads`
- `POST /api/messages`

### 7.3 骑手配送流程

```text
骑手登录 -> 查看任务 -> 接单 -> 已取餐 -> 送达完成 -> 查看统计/历史
```

关键接口：

- `GET /api/rider/dashboard`
- `GET /api/rider/tasks`
- `PUT /api/rider/tasks/{id}`

### 7.4 管理员治理流程

```text
管理员登录 -> 查看主体列表 -> 审核/冻结/解冻 -> 查看订单异常
```

关键接口：

- `GET /api/admin/users`
- `GET /api/admin/merchants`
- `GET /api/admin/riders`
- `GET /api/admin/orders`

## 8. 订单状态说明

当前订单状态以 `order-service` 为准，前端负责展示和触发合法动作。常见状态包括：

- `pending_payment`：待支付。
- `pending_accept`：待接单或待商家/骑手推进。
- `delivering`：配送中。
- `completed`：已完成。
- `cancelled`：已取消。

前端展示可能会转换为中文文案，例如“待支付”“待取餐”“配送中”“已完成”“已取消”。

## 9. 前后端分工

前端负责：

- 页面展示、表单交互、路由保护和基础状态管理。
- 通过 `frontend/src/utils/api.js` 调用 `/api/...`。
- 在 Playwright E2E 中使用 mock API 稳定覆盖页面流程。

后端负责：

- 认证和角色身份。
- 用户、商家、骑手、订单、优惠券、评价、消息等业务数据持久化。
- 跨服务内部接口、库存预占/释放、优惠券锁定/核销、支付状态推进。
- Gateway 路由、Nacos 配置、Sentinel 规则和 Feign 治理。

## 10. 注意事项

1. 普通用户、商家、骑手、管理员使用不同账号登录。
2. 角色切换建议先退出当前账号再重新登录。
3. 商家和骑手不能参与普通用户购物流程。
4. 游客只能访问公开浏览能力。
5. 前端 E2E mock 结果不能替代真实 Gateway 冒烟结果。

## 11. 后续增强方向

- 接入真实支付网关或回调验签。
- 增加更完整的骑手调度和地理位置策略。
- 扩展订单取消、退款和补偿自动化规则。
- 将订单消息升级为实时推送。
- 增加真实环境多角色端到端冒烟脚本。
