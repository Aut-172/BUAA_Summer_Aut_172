# 项目交付说明

## 1. 交付目标

当前项目已经从早期前端原型阶段推进到“前端 + 微服务后端 + 容器部署脚本”的阶段性交付。交付目标是：

- 提供一套可运行的前端体验
- 形成游客 / 普通用户 / 商家 / 骑手四角色闭环
- 通过 API Gateway 暴露清晰稳定的 `/api/...` 接口
- 通过 `services/` 下的 Spring Boot 微服务承载真实后端能力

---

## 2. 当前交付内容

### 前端页面与交互

- 首页
- 搜索页
- 商家详情页
- 商品详情页
- 购物车页
- 订单页
- 登录注册页
- 角色资料页
- 商家后台
- 商家商品编辑页
- 骑手工作台
- 聊天页
- 商品评价页

### 角色体系

- 游客（只浏览）
- 普通用户（消费链路）
- 商家（经营链路）
- 骑手（履约链路）

### 本地接口适配与真实后端

- 所有请求统一走 `/api/...`
- 前端真实请求入口为 `src/utils/api.js`
- Playwright E2E 仍使用 `e2e/support/mockApi.js` 覆盖前端场景
- 微服务后端由 `services/` 下六个业务服务和 `api-gateway` 提供

## 4. 当前仍然属于 mock / 可继续增强的部分

当前大部分消费者、订单、结算、骑手和互动链路已有微服务后端。以下部分仍需在真实后端或联调层面继续增强：

1. 商家后台真实接口
   - 前端已调用 `/api/merchant/dashboard`、`/api/merchant/profile`、`/api/merchant/products/**`
   - 当前 `merchant-service` 尚未暴露对应 Controller

2. 管理员商家管理
   - 前端和 Gateway 已记录 `/api/admin/merchants/**`
   - 当前后端尚未暴露管理员商家审核、冻结、解冻接口

3. Gateway 路由核对
   - `engagement-service` 已实现 `GET /api/user/reviews`
   - 当前 Gateway 的 `/api/user/**` 泛路由可能截获该路径

4. 支付链路
   - 当前为模拟支付成功和支付流水记录
   - 后续可接真实支付网关或独立支付回调验签

5. 补偿自动化
   - 订单服务已有补偿记录落点
   - 后续可增加调度任务自动重试库存释放、优惠券释放、评价标记等失败操作

---

## 5. 推荐后端接入顺序

建议按以下顺序做剩余后端补齐和真实联调：

### 第一阶段：修正路由和冒烟
- `/api/user/reviews`
- `/api/health`
- `/api/captcha`

### 第二阶段：商家后台
- `/api/merchant/dashboard`
- `/api/merchant/profile`
- `/api/merchant/products`
- `/api/merchant/products/{id}`

### 第三阶段：管理员商家管理
- `/api/admin/merchants`
- `/api/admin/merchants/{id}/audit`
- `/api/admin/merchants/{id}`
- `/api/admin/merchants/{id}/unfreeze`

### 第四阶段：真实 Gateway 端到端验收
- 消费者下单支付
- 商家接单/订单更新
- 骑手接单送达
- 用户评价和消息
- 管理员用户/商家/骑手/订单管理
