# 项目交付说明

## 1. 交付目标

当前项目交付目标不是“完整后端系统”，而是：

- 提供一套可运行的前端原型
- 形成游客 / 普通用户 / 商家 / 骑手四角色闭环
- 暴露清晰稳定的 `/api/...` 接口形状
- 方便后端同学使用 Spring Boot + MySQL + Redis 接入真实业务逻辑

---

## 2. 当前交付内容

### 前端页面与交互

- 首页
- 搜索页
- 商家详情页
- 商品详情页
- 购物车页

- 登录注册页
- 角色资料页

- 骑手工作台
- 聊天页

### 角色体系

- 游客（只浏览）
- 普通用户（消费链路）
- 商家（经营链路）
- 骑手（履约链路）

### 本地接口适配

- 所有请求统一走 `/api/...`
- 本地由 `vite.config.js` 提供 mock 实现
- 后端接入时可逐步替换 mock

## 4. 当前仍然属于 mock / 可继续增强的部分

虽然前端闭环已经基本形成，但以下部分仍属于“前端模拟真实业务”的范畴，后端接入时建议重点接手：

1. 真实用户鉴权
   - 当前账号角色由 mock 数据直接返回
   - 后续建议改为 JWT + 登录拦截

2. 真实库存与事务一致性
   - 当前库存变更已有 API 入口
   - 但底层仍是内存 mock，不是数据库事务

3. 支付链路
   - 当前为前端触发支付接口后直接变更状态
   - 后续可接真实支付网关或模拟支付中台

4. 骑手派单 / 抢单逻辑
   - 当前已有状态流转
   - 后续可细化为未分配任务池 / 我的任务 / 历史任务

5. 商家订单更细颗粒度状态
   - 目前主要是配送中 / 已完成
   - 后续可增加待接单 / 制作中 / 已出餐 等中间状态

## 5. 推荐后端接入顺序

建议队友按以下顺序接入后端：

### 第一阶段：基础认证与用户体系
- `/api/auth/login`
- `/api/auth/register`
- `/api/user/profile`

### 第二阶段：商品与商家
- `/api/merchants`
- `/api/merchants/:id`
- `/api/merchant/profile`
- `/api/merchant/products`
- `/api/merchant/products/:id`

### 第三阶段：购物车与下单
- `/api/cart/items`
- `/api/cart/clear`
- `/api/checkout`
- `/api/orders`
- `/api/orders/:id/pay`
- `/api/orders/:id/cancel`
- `/api/orders/:id/complete`

### 第四阶段：履约链路
- `/api/merchant/orders`
- `/api/merchant/orders/:id`
- `/api/rider/tasks`
- `/api/rider/tasks/:id`
- `/api/delivery/:orderId`
