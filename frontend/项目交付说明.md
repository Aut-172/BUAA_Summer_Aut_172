# 项目交付说明

## 1. 交付目标

当前项目已经从早期前端原型推进到“React 前端 + 微服务后端 + 容器化部署 + 云原生治理实验”的阶段性交付。交付目标是：

- 提供可运行的多角色前端体验。
- 形成游客、普通用户、商家、骑手、管理员五类身份的核心业务闭环。
- 通过 API Gateway 暴露统一稳定的 `/api/...` 接口。
- 通过 `services/` 下的 Spring Boot 微服务承载真实后端能力。
- 提供 Docker Compose、Kubernetes 示例部署、CI/CD、测试和治理实验材料。

## 2. 当前交付内容

### 2.1 前端页面与交互

- 首页和搜索页。
- 商家详情页。
- 购物车和结算页。
- 优惠券页。
- 订单页和订单详情相关动作。
- 登录注册页。
- 用户资料页。
- 商家中心。
- 骑手中心。
- 管理中心。
- 消息线程和订单会话详情。
- 商品评价页和图片上传预览。

### 2.2 后端微服务

- `api-gateway`：统一入口和路由优先级控制。
- `merchant-service`：商家、商品、分类、搜索、推荐、商家后台、管理员商家管理。
- `user-service`：消费者认证、资料、地址、购物车、收藏、管理员用户管理。
- `order-service`：下单、订单查询、订单状态推进、商家订单、管理员订单、内部订单接口。
- `settlement-service`：优惠券、锁券、核销、模拟支付、支付查询。
- `fulfillment-service`：骑手认证、骑手资料、配送任务、管理员骑手管理。
- `engagement-service`：评价、图片上传、评分、消息会话。
- `common-lib`：JWT、响应包装、异常、Feign 常量和公共拦截器。

### 2.3 部署与治理材料

- Docker Compose 本地启动链路。
- K8s 示例部署清单。
- GitHub Actions CI/CD。
- Nacos Discovery / Config。
- Sentinel 限流与熔断规则。
- Feign 超时和日志治理。
- HPA、Sentinel、故障容错实验脚本与报告。

## 3. 当前已闭环能力

### 3.1 普通用户

- 注册和登录。
- 浏览、搜索、推荐商家与商品。
- 管理个人资料、地址和收藏。
- 加入购物车、更新数量、清空购物车。
- 领取和查看优惠券。
- 提交订单。
- 模拟支付订单并查看支付记录。
- 取消订单、确认完成。
- 查看配送信息。
- 提交图文评价。
- 查看和发送订单消息。

### 3.2 商家

- 注册和登录。
- 查看经营看板。
- 修改店铺资料。
- 新增、编辑、删除商品。
- 管理规格、库存和商品图片字段。
- 查看本店订单。
- 更新本店订单状态。
- 参与订单消息沟通。

### 3.3 骑手

- 注册和登录。
- 查看骑手资料和配送统计。
- 查看待接任务、我的任务和已完成历史。
- 接单、已取餐、送达完成。
- 修改骑手资料。
- 参与订单消息沟通。

### 3.4 管理员

- 登录管理中心。
- 查看用户、商家、骑手和订单列表。
- 审核商家和骑手。
- 冻结和解冻用户、商家、骑手。
- 查看订单详情。

### 3.5 游客

- 浏览首页。
- 搜索商家和商品。
- 查看商家详情和公开评价。
- 购买、评价、消息等私有能力会跳转登录。

## 4. 当前仍需说明的边界

以下能力已经具备演示或阶段实现，但不应包装成完整生产级能力：

1. 支付链路仍是模拟支付成功和支付流水记录，尚未接真实支付网关、退款、回调验签。
2. 骑手任务流转可用，但调度策略仍偏简单，尚未接地图、距离、容量和派单优化。
3. 消息已在后端持久化为订单会话，但不是实时通讯，尚未接 WebSocket 或推送服务。
4. 图片上传支持本地/OSS 配置，但生产环境还需补充对象存储权限、CDN、防盗链和生命周期策略。
5. 跨服务容错已覆盖商家看板依赖订单服务的链路，其他链路仍需继续设计故障实验。
6. 前端 Playwright E2E 默认使用 mock API，真实 Gateway 端到端冒烟需要先启动完整后端或云端环境。

## 5. 推荐验收顺序

### 第一阶段：本地构建与单测

- 执行 `powershell -ExecutionPolicy Bypass -File scripts\test-microservices.ps1`。
- 执行 `powershell -ExecutionPolicy Bypass -File scripts\test-b-side-services.ps1`。
- 执行 `cd frontend && npm.cmd run build && npm.cmd run test:ci`。

### 第二阶段：前端页面流程

- 执行 `cd frontend && npm.cmd run e2e`。
- 若本机 Playwright 浏览器权限异常，以 CI 或可用机器结果为准。

### 第三阶段：真实后端联调

- 使用 Docker Compose 或 K8s 启动完整服务。
- 验证 `/actuator/health`、`/api/health`、`/api/captcha`。
- 按消费者、商家、骑手、管理员四类登录身份逐条验收核心链路。

### 第四阶段：部署与治理核对

- 检查 Nacos Config 是否发布。
- 检查 Sentinel 规则是否加载。
- 检查前端 `/api` 代理是否指向 Gateway。
- 复核 `reports/performance/`、`reports/sentinel/`、`reports/fault/` 下的最新报告。

## 8. 最终说明

本项目当前可以作为：

- 课程项目阶段性交付版本。
- 前后端真实联调基座。
- Spring Cloud 微服务拆分和治理实践样例。
- Docker Compose / Kubernetes 部署演示样例。
- 性能、Sentinel、故障容错实验材料样例。

后续继续增强时，优先围绕真实支付、骑手调度、实时消息、更多跨服务容错实验、真实环境端到端冒烟和生产级对象存储策略推进。
