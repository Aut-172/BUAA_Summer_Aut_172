# 前端接口对接说明文档

## 1. 文档目标

本文按当前微服务代码和前端 `frontend/src/utils/api.js` 更新接口记录，用于阶段收尾、联调核对和后续 CI/CD 冒烟脚本编写。

当前接口统一以 `/api` 为前缀，由 `api-gateway` 路由到后端微服务。前端请求入口是 `frontend/src/utils/api.js`，Playwright mock 数据位于 `frontend/e2e/support/mockApi.js`。

## 2. 通用约定

| 项目 | 约定 |
| --- | --- |
| 响应包装 | 多数接口返回 `Result<T>`：`code`、`message`、`data`；分页接口返回 `PageResult<T>`：`code`、`message`、`data`、`total`、`page`、`pageSize`。 |
| 鉴权 | 登录后前端通过 `Authorization: Bearer <token>` 传递 JWT。 |
| 角色 | `consumer`、`merchant`、`rider`、`admin`。 |
| 公共接口 | `GET /api/health`、`GET /api/captcha`。 |
| 服务间调用 | 前端不直接调用 `/internal/**`；内部接口由 OpenFeign 按 Nacos 服务名调用。 |

## 9. 收尾建议

1. 商家后台、商品管理和管理员商家管理接口已由 `merchant-service` 承接；后续重点是补真实 Gateway 多角色冒烟脚本。
2. `GET /api/user/reviews` 的 Gateway 路由优先级已修正；若后续想进一步收敛接口，也可统一改为 `/api/reviews/mine`。
3. CI 已由 `.github/workflows/ci.yml` 承接，覆盖前端单测、Playwright E2E、前端构建、后端微服务矩阵测试，以及 main 分支镜像构建和 kind/K8s 部署。
4. 交付前重新执行后端全量测试、前端单测、前端 E2E，并把最新报告归档到 `reports/testing/`。
5. 支付、实时消息、骑手调度和更多跨服务故障实验仍属于后续增强范围，接口变更时需同步更新本文档和 `frontend/src/utils/api.js`。
