# 最终收口检查说明

## 1. 当前项目状态

截至 2026-09-03，项目已经完成以下阶段性交付：

- React 前端页面和多角色路由保护。
- API Gateway 统一 `/api` 入口。
- 六个业务微服务和一个公共库。
- 多 schema 数据库初始化脚本。
- Docker Compose 本地运行链路。
- Kubernetes 示例部署清单和 CI/CD 部署脚本。
- Nacos Config、Sentinel 规则、Feign 治理、图片存储配置。
- 微服务测试、B 侧专项测试、性能对比、Sentinel 和故障容错实验报告。

## 3. 收口验收命令

后端全量测试：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\test-microservices.ps1
```

B 侧专项测试：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\test-b-side-services.ps1
```

前端构建和单测：

```powershell
cd frontend
npm.cmd run build
npm.cmd run test:ci
```

前端 E2E：

```powershell
cd frontend
npm.cmd run e2e
```

完整环境启动：

```powershell
copy .env.example .env
$env:COMPOSE_PARALLEL_LIMIT=1
docker compose up -d mysql redis nacos
docker compose run --rm db-init
docker compose up --build
```

## 5. 仍需如实说明的边界

1. 支付仍是模拟支付成功和支付流水记录。
2. 骑手分配可完成任务流转，但不是复杂调度算法。
3. 消息已后端持久化，但不是实时通讯。
4. 图片上传可切本地或 OSS，但生产环境还需要补存储权限、CDN、防盗链、生命周期等策略。
5. 故障容错实验已覆盖商家看板链路，尚未覆盖所有跨服务链路。
6. Playwright E2E 默认走 mock API，真实 Gateway 端到端验收需要完整运行环境。

## 7. 手工验收建议

### 7.1 普通用户链路

- 登录。
- 搜索商品或进入商家详情。
- 加购。

- 下单。
- 支付。
- 查看订单和配送信息。
- 确认完成。
