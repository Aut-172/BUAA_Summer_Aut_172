# 前端架构与后端接口需求分析报告

> **项目名称**：生活助手平台（Life Assistant Platform）
> **前端技术栈**：Vanilla JS + Vite 5（无框架 SPA）
> **目标**：为 Spring Boot 后端开发提供完整的接口需求与架构上下文

---

## 一、前端技术架构总览

### 1.1 核心技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 构建工具 | Vite 5 | 开发服务器 + 构建打包 |
| UI 框架 | **无**（Vanilla JS） | 纯 JavaScript SPA，无 Vue/React/Angular |
| 路由 | **Hash 路由**（`window.location.hash`） | 自定义实现，非 Vue Router |
| 状态管理 | **localStorage 持久化** | 自定义 `loadState()` / `saveState()` |
| 样式 | 原生 CSS（2310 行） | CSS 自定义属性主题，响应式布局 |
| HTTP 客户端 | `fetch()` 封装 | `src/api.js`，统一 `/api` 前缀 |
| Mock 服务 | Vite Plugin + Node HTTP Server | 内嵌在 `vite.config.js`，端口 3001 |

### 1.2 项目结构

```
/
├── index.html              # HTML 入口
├── package.json            # 依赖与脚本
├── vite.config.js          # Vite 配置 + Mock API Server（685行）
└── src/
    ├── main.js             # 入口：import './app.js'
    ├── app.js              # 全部应用逻辑（4368行）
    ├── api.js              # API 客户端层（150行）
    └── style.css           # 全局样式（2310行）
```

> **注意**：前端**没有** `src/views/`、`src/store/`、`src/router/` 等目录，所有代码集中在 [`src/app.js`](src/app.js) 一个文件中。

### 1.3 路由表（Hash 路由）

| 路由 | 页面 | 角色限制 |
|------|------|----------|
| `#/home` | 首页（商家列表 + 搜索） | 全部角色 |
| `#/merchant` | 商家详情页 | 全部角色 |
| `#/product/:id` | 商品详情页 | 全部角色 |
| `#/search` | 搜索结果页 | 全部角色 |
| `#/product-reviews/:id` | 商品评价页 | 全部角色 |
| `#/login` | 登录页 | 游客 |
| `#/register` | 注册页 | 游客 |
| `#/cart` | 购物车 | consumer |
| `#/orders` | 订单列表 | consumer |
| `#/profile` | 个人中心（按角色展示不同界面） | 已登录 |
| `#/merchant-dashboard` | 商家后台 | merchant |
| `#/merchant-product-editor/:id` | 商品编辑页 | merchant |
| `#/rider-dashboard` | 骑手工作台 | rider |
| `#/chat` | 聊天页面 | consumer/merchant |

### 1.4 角色体系

| 角色 | 标识 | 首页视图 | 可访问页面 |
|------|------|----------|------------|
| 游客（guest） | `state.auth.user === null` | 通用首页 | home, merchant, product, search, login, register |
| 普通用户（consumer） | `state.auth.role === 'consumer'` | 消费首页 | 全部（除商家/骑手后台） |
| 商家（merchant） | `state.auth.role === 'merchant'` | 商家首页 | 全部（除骑手后台） |
| 骑手（rider） | `state.auth.role === 'rider'` | 骑手首页 | 全部（除商家后台） |

### 1.5 状态管理数据结构

前端全局状态存储在 `state` 对象中，通过 `localStorage` 持久化。核心字段：

```javascript
{
  auth: { user, role, merchantId, riderId },
  merchants: [],           // 商家列表（含商品）
  orders: [],              // 订单列表
  cart: [],                // 购物车
  coupons: [],             // 优惠券
  profile: { nickname, phone, avatar, serviceArea },
  addresses: [],
  selectedMerchantId: null,
  orderTab: 'all',
  riderOnline: false,
  riderFilters: { tab: 'available' },
  chatThreads: {},         // { merchantId: [...] }
  reviewDrafts: {},
  activeProductSelections: {},
  loading: false,
  error: null,
  route: '#/home',
  toast: null
}
```

## 三、认证与全局配置

### 3.1 当前认证机制

| 项目 | 当前实现 | 后端建议 |
|------|----------|----------|
| 认证方式 | **无 Token**，session 内存存储 | 建议改为 **JWT（Access Token + Refresh Token）** |
| 凭证传递 | 无 Authorization Header | 前端需在 `api.js` 的 `request()` 中添加 `Authorization: Bearer <token>` |
| 登录响应 | 返回 `user` 对象 | 需增加 `accessToken`、`refreshToken`、`expiresIn` 字段 |
| 注册 | 默认角色为 consumer | 保持，可扩展角色选择 |
| 验证码 | 前端硬编码 `7A9Q` | 后端需提供验证码生成/校验接口 |

### 3.2 建议的认证流程

```
登录/注册
  ↓
后端返回 { accessToken, refreshToken, user }
  ↓
前端存储 token 到 localStorage
  ↓
每次请求在 Authorization Header 携带 Bearer token
  ↓
token 过期 → 使用 refreshToken 刷新
  ↓
刷新失败 → 跳转登录页
```

### 3.3 CORS 配置

当前前端通过 Vite 代理解决跨域：

```javascript
// vite.config.js
proxy: {
  '/api': {
    target: 'http://127.0.0.1:3001',
    changeOrigin: true
  }
}
```

**后端需配置 CORS**，允许来自开发服务器（如 `http://localhost:5173`）的跨域请求。

### 3.4 错误码约定

前端错误处理逻辑（[`src/api.js`](src/api.js)）：

```javascript
async function request(path, options = {}) {
  const response = await fetch(API_BASE + path, {
    headers: { 'Content-Type': 'application/json' },
    ...options,
    body: options.body ? JSON.stringify(options.body) : undefined
  });
  const data = await response.json();
  if (!response.ok) throw new Error(data.message || '请求失败');
  return data;
}
```

**后端响应格式建议：**

| 场景 | HTTP 状态码 | 响应体 |
|------|-------------|--------|
| 成功 | 200 | `{ ...业务数据 }` |
| 业务错误 | 400 | `{ "message": "错误描述" }` |
| 未认证 | 401 | `{ "message": "请先登录" }` |
| 无权限 | 403 | `{ "message": "权限不足" }` |
| 资源不存在 | 404 | `{ "message": "资源不存在" }` |
| 服务器错误 | 500 | `{ "message": "服务器内部错误" }` |

### 3.5 前端期望的 API 约定

1. **所有接口返回 JSON**，无 XML 或其他格式
2. **错误时返回 `message` 字段**，前端直接展示给用户
3. **订单状态流转**：`待支付 → 待取餐 → 配送中 → 已完成`（或 `已取消`）
4. **商品规格体系**：`specGroups`（规格维度定义）+ `specs`（具体规格变体）组合模式
5. **图片处理**：前端支持 Base64 上传和 URL 展示，后端需提供图片存储方案
